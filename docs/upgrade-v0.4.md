# 升级到 v0.4.0

1. 停止服务和 Worker，完整备份 data/（包括 SQLite WAL/SHM）与 .env。
2. 在新代码目录使用旧配置和数据；不要覆盖令牌或重新 init。
3. 首次打开数据库会依次补齐 schema 1/2/3 到 4 的迁移，新增 followups、followup_history 及索引。
4. 旧的已关闭运行中，未消费且通过归属、收件人及时间校验的隔离事件会生成待办。重复打开不重复创建，原运行、审批、成果记录保持不变。
5. 核对待办数量、原运行状态与审计。初始待办不设负责人或期限，由操作员安排。

新生成的验收档案 manifest.schemaVersion 为 2，包含跟进历史。读取档案的下游系统需要接受新版本；已有导出文件不被修改。

v0.3 及更早程序不能打开 schema 4。回滚时停止新版，保存升级后的处理记录，再恢复升级前代码和完整数据库；与实际业务网关核对已发生动作，避免重复发送。不要直接降低 schema_version。

已用未修改的 v0.3.0 运行时创建数据库并完成本地升级验证，见 reports/v0.4.0/v3-upgrade.json。测试业务数据为显式合成 fixture，不是客户生产库。
