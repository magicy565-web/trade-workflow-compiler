# 架构、状态语义与明确不支持的内容

## 数据流

```text
请求 + 明确企业事实
        ↓
规则解析 / 可选模型选择（只返回模板枚举与原文证据）
        ↓
三套 Playbook → WorkflowSpec v1 → 静态验证
        ↓
不可变 draft → 独立 approver 发布（绑定 spec hash）
        ↓
operator 创建 run（固定 snapshot + request idempotency key）
        ↓
SQLite 状态解释器 ← HTTP 事件收件箱 / 人工审批
        ↓
OpenMausBot 只读任务 或 专用 HTTP 商业动作网关
```

编译成功表明静态配置合法，不证明外部服务此刻健康或业务判断正确。`doctor` 单独探测。每个节点执行前重新校验当前 Registry 与固定哈希，外部网关还会执行健康契约检查。

## 五种节点

`agent_task` 读取或生成草稿；`action` 产生外部商业效果；`human_approval` 审批具体动作输入；`wait_event` 等待受认证事件；`decision` 只对一个显式字段执行等值比较。

v1 是有向无环流程，所有节点必须可达。输入节点必须支配消费者：每条执行路径都必须经过数据生产者。外部动作的审批节点也必须支配动作，审批与动作引用同一个输入，拒绝/超时只能结束。没有 `eval`、任意代码节点、任意表达式、用户提供命令执行或自动新增能力。

模板源码和 Capability Registry 是管理员维护的业务协议。当前没有独立 Worker 发现服务，也没有运行中动态重写流程。Registry 中的真实 bot ID 或网关绑定就是能力到执行方的映射。

## 企业事实与来源

编译器不会从一句“开发美国买家”臆造公司名、MOQ、预算或联系方式。缺少关键事实会阻止发布。每个任务收到不可变的完整企业上下文与原始经营需求，另附其输入契约数据；不依赖中间 Worker 回传的公司资料作为权威来源。

研究输出要求结构化来源 URL、抓取时间、摘录和验证标记。这些是 Worker 提供的记录，不是独立事实核验。本版没有网页抓取器或原始快照存储，也没有检测所有伪造来源的算法；人审仍须访问原始来源。

## 预算

`budgetMicros` 是本次运行的授权上限；Registry 的 `maxCostMicros` 是每次任务的保留额度。编译按最保守路径（所有节点、允许重试总和）计算上界，运行每次新尝试先预留再发出任务。只读任务最多按配置重试，外部动作只发出一次。

额度是整数 USD 微元，不是价格报价；默认每能力 500,000 微元是部署初始策略值，不代表真实市场收费。请按实际服务配置修改。提供方返回实际费用时单独计入；超过该节点授权额度会停止后续调度，但已经发生的费用不能撤销。远端 OpenMausBot 模型额度必须另行设置；可选模型模板解析费用也不属于 run 账本。

## 持久化与恢复

SQLite WAL 保存 definitions、runs、approvals、events、audit、suppression。写入使用事务；每个 run 使用租约限制重复调度。业务操作之前先落盘 `running`，成功之后保存结构化回执。操作是否真实发生不明确时进入 `NEEDS_RECONCILIATION`，绝不根据超时猜测失败然后再次发送。

终态：`COMPLETED / REJECTED / TIMED_OUT / FAILED / CANCELLED / NEEDS_RECONCILIATION`。最后一种仅允许独立审批人用提供方真实回执解除。它不是“重试”按钮。

取消停止本地后续调度；已经交给远端的研究、邮件或样品动作不保证同时取消或撤销。失败的只读任务耗尽重试后没有任意跳步恢复接口，需要修复原因后创建新运行。若涉及外部动作不明，先对账，不能绕过对账重新运行。

## 事件范围

事件按 tenant、事件类型、correlationId、时间窗口匹配并最多消费一次。事件到达早于等待节点但晚于运行开始时可以保留；过期、错租户、错关联事件不会推进流程。事件 ID 复用且内容不同会拒绝。

一个运行只发送给一个收件人，只等待一次业务事件；没有批量 fan-out、持续会话循环或多轮销售 CRM。需要批量时逐客户创建独立运行和关联 ID。买家开发最终分类只是提供销售判断，不声称已经生成询盘、报价或订单。

## SQLite 与 Temporal

默认 embedded 调度器与 API 同进程；内置持久化不依赖 Temporal 即可运行。`integrations/temporal` 仅把持久化时钟和节点推进交给 Temporal，商业状态、内容、审批仍在 TWC 内。切换时必须设 `TWC_SCHEDULER=external`。可选包尚未对真实 Temporal 验证，不作为本版完成验收范围。

未实现 PostgreSQL、多区域高可用、严格多租户远端凭证/记忆隔离。部署目标是一企业一实例，避免用一个带共享记忆的 bot 服务多个不相关企业。

## v0.2 增量

`Batches` 是现有执行器的薄编排层，不是第二套 Agent Runtime。源任务在多买家起草前暂停；单事务建立逐客户运行、继承前缀结果、停止源任务，并用共享预算账本约束所有后续派发。发布后的 spec 不变，每次运行还会检查其哈希与已发布版本一致。

`EventInbox` 增加持久化 correlation → run + recipient 映射、提前事件保留、错误归属隔离、分页查看与重检。外部回执登记与节点成功共用事务，不能先把任务标成成功再补关联。结果不明的外部动作暂停所在批次，不自动重发。HMAC 入口属于网关协议，不是渠道原生集成。

可选 Temporal 目录仍保留且未完成 SDK/真实服务验收。批次子任务的 Temporal 工作流启动与 signal bridge **尚未实现**；v0.2 默认用 embedded 调度器，external 模式需要外部调度者自行推进每个子运行，不可据此声称批次已接入 Temporal。
