# v0.4 → v0.5 升级

v0.5 建立在 v0.4 人工待办基础上。仍使用数据库 schema 4；没有新增表或自动改写旧流程、旧价格和审批。v0.3 用户应先阅读 v0.4 迁移说明。先停止服务、备份 data/ 与 .env，再切换版本；不要重新 init。

1. 更新源码和预编译 dist；开发环境用 `npm ci --ignore-scripts`、`npm run check`。
2. 不使用定价接入时，原 capabilities.local.json 无需增加条目，旧流程可按原绑定运行。
3. 使用定价接入时，按 [接入说明](pricing-bridge.md) 合并两个新能力并配置真实端点和 viewer 密钥；原本地 Registry 不会自动被覆盖。旧 Registry 缺少新能力时，编译返回 blocked，不自动回退到旧报价起草。
4. 运行 doctor 检查相关能力，重新编译新版本并经独立人员发布/批准具体发送内容。
5. 验证真实服务、网关幂等、撤回、过期和异常对账后才用于实际业务。附带的跨项目联调报告只使用隔离合成数据。

价格内容或能力绑定变化后，不沿用旧发送审批。已发送报价在远端撤回不会自动撤销既有邮件，也不会自动向客户发送更正；需要人工处理。
